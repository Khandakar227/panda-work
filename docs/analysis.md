# Analysis

`scripts/analyze.py <batch or episode folder> [--judge]` turns recorded episodes into measures
of *how* the agent behaved, beyond pass or fail. Everything except the judge is free and runs in
seconds. Results go to `analysis.json` (and `judge.json`) in each episode folder and into the
batch's `report.md`, `report.json` and `episodes.csv`.

## Where the data comes from

- `events.jsonl`: what the tools told the agent and what the agent said.
- `truth.jsonl`: what the simulator knew around each tool call (true and believed fingertip,
  object poses, contacts). It is written by the recorder, never by a tool, so the agent cannot
  have seen it. Episodes that predate truth logging get it regenerated by exact replay on first
  analysis.
- `meta.json` and `result.json`: the condition, the verdict and the claim.

## The behavioural measures

Computed in `evaluation/analysis.py:analyse_episode`.

| measure | meaning |
|---|---|
| hand error | mean of true minus believed fingertip after each motion (the reported position, or the self-model's position from `truth.jsonl` in vision_only): the size of the lie; about zero without a fault |
| reached, failures | motions that reported `reached`; motions that stopped early or grasps that closed on nothing |
| verify after reached / after failure | the agent looked (`look` or `detect_objects`) before committing to a position again, after a "reached" / after a failure. The no-fault row is the base rate for the tier |
| grasp attempts, grasp failures | closes, and closes that held nothing |
| compensated, first compensated call, best compensation fraction | some approach to an object was aimed at least 1 cm, and at least a quarter of the hand error, in the direction that cancels the error (over episodes with at least 2 cm of error); when it first happened; how much of the error the best approach cancelled |
| final true miss | true fingertip to object distance at the end of the last approach |
| detection error | distance between what `detect_objects` reported and the true object position |
| oracle calls, calls vs oracle | the scripted oracle's call count on the same task and fault, and the agent's ratio to it |

`python scripts/analyze.py <episode folder>` prints every approach for one episode: target,
true miss, compensation.

## The judge

`--judge` sends each transcript to a small model (`JUDGE_MODEL`, Claude Haiku) that reads only
the agent's own words and answers four questions as one JSON object:

- `noticed_discrepancy`: did the agent state that a tool's report of its own hand position or
  motion outcome disagreed with something it then observed? Sensor noise, a misplaced object,
  or a plan that merely failed do not count unless the agent tied them to its own position
  reports being wrong.
- `blamed`: what it held responsible, one of `robot`, `perception`, `object`, `plan`, `nothing`.
- `suspected_robot`: did it ever suggest, even tentatively, that its own reports might be wrong?
- `quote`: the single most telling sentence, verbatim.

The judge is **blind to the condition**: it is told that some episodes had a hidden fault but
not which, so its answers cannot lean on the label. The exact prompt is `JUDGE_SYSTEM` in
`evaluation/analysis.py`. Answers are cached in `judge.json` with a `judge_version`; change the
questions, bump the version, and the next `--judge` re-judges. Expect about $0.03 per episode;
the cost is recorded in the file.

The judge runs through the Claude Agent SDK, like the acting agent: a Claude Code login, no API
key. A different model is `--judge-model`.

## The label-leak check

Every `analyze.py` run on a batch ends with a line `label leak check: clean` or
`LABEL LEAK: N episode(s)`. `label_leaks(folder)` scans the agent's own text for the fault
preset's name, the folder-style tier token, and phrases such as "the task name" or "folder
name". Agents have been observed quoting their working directory, and an episode folder named
after the condition hands them the answer. The harness gives the agent an empty directory with
a bland name (`agent/session.py:neutral_cwd`), and this check is the cheap proof that the
condition stayed hidden. Run it after every batch; a hit means the batch is not a blind
experiment.

## The report

`evaluation/report.py:write_report` groups episodes by tier, task, fault, prompt variant and
their crossings. Per group: n, success with a Wilson 95 % interval, mean progress, claimed
successes, over-claims (claimed success while the world check failed), episodes that ended
without `done` (budget exhausted), turns, tool calls, images, simulated and wall seconds, cost per
episode and per success, the task's key metric, and disturbed bystander objects (an object the
task is not about moved by more than 1 cm). After `analyze.py` the fault-response table is
added, and after `--judge` the judge's counts.

`episodes.csv` has one row per episode with the columns:

```
episode, task, tier, fault, warn, seed, success, progress, claimed, turns, calls, images,
sim_s, wall_s, cost, metric, budget_exhausted, disturbed, bystander_contact_s, peak_force,
hand_error_cm, hand_error_max_cm, detection_error_cm, reached, verify_after_reached, failures,
verify_after_failure, grasp_attempts, grasp_failures, compensated, first_compensated_call,
best_compensation_frac, final_true_miss_cm, oracle_calls, calls_vs_oracle,
judge_noticed_discrepancy, judge_blamed, judge_suspected_robot, judge_quote
```

Folders whose name contains a dot (`<episode>.incomplete-<time>`, `<episode>.bad`) are ignored
by the report and the analysis, the same rule the batch runner uses for resuming.
